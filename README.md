# 动力轮代码 — APO-DL 电调 + 编码器 键盘遥控测试

ESP32-S3 驱动**两路 APO-DL 无刷电调（RC 航模 PWM 信号）**的最小可用程序：用串口键盘 `w/a/s/d` 遥控后轮差速底盘前进/后退/转向，并实时读取 AB 编码器计数。

> **这个分支是什么**：独立的**动力轮 bring-up** 分支，**不含任何传感器或自动算法**，就是把电调、电机、编码器接对、转对、能用键盘开起来。它定下的电调/编码器引脚与驱动方式（RC-PWM + 4× 正交编码），正是 `算法2` 闭环底盘 `components/control/chassis/` 的硬件基础——两者引脚一致。先在这里把电机调通，再上 `算法2` 做闭环跟随。

---

## 概述

这个程序是整个「跟随行李箱」项目动力系统的**裸机原型 / 手动验证台**。它只做三件事：

1. **驱动电调** — 用 ESP32-S3 的 LEDC 硬件 PWM 生成标准 RC 航模脉冲，控制 APO-DL 无刷电调
2. **读取编码器** — 用 GPIO 边沿中断实现 4 倍频 AB 正交编码解码，实时显示脉冲计数
3. **键盘遥控** — 通过板载 USB-JTAG 串口接收按键指令，实现手动前后左右操作

整个程序只有 **一个 `main.c` 文件**，没有依赖任何自定义组件库。非常适合作为硬件验证的第一步——先确认电机和编码器的接线正确，然后才能信任后续闭环算法的测试结果。

## 功能

### 核心功能
- **RC-PWM 电调驱动**：用 LEDC（50Hz，14 位）生成航模舵机脉冲（1000–2000µs，**1500µs=停**）驱动两路 APO-DL 电调
- **键盘遥控**：通过 USB 串口键入 `w/s/a/d/x` 控制前进/后退/左转/右转/停
- **可调速度**：`+`/`-` 调整速度力度（脉冲偏移 `speed_delta_us`），范围 100~500µs
- **编码器读数**：AB 正交编码器 4× 解码，`c` 查看左右计数（**仅显示，不参与控制**）
- **死人停车**：每条移动指令最多执行 **1.2s** 就自动停（必须持续按键才持续走）

### 什么是"死人停车"（Dead-man Switch）？
这是工业设备中常见的安全机制：操作者必须持续按住/按下按钮才能保持设备运转，一旦松手（或系统卡住），设备自动停止。本程序中，每次按下 w/s/a/d，电机只会运行 1.2 秒，超过时间自动回到中立位 1500µs。要持续走，必须持续按键（每次按键重置计时器）。

## 硬件连接（与 `算法2` 闭环底盘一致）

### 电调连接

| 信号 | ESP32-S3 GPIO | 接到哪里 |
|------|---------------|----------|
| 左电调信号 S | **GPIO4** | APO-DL **A 通道** S 脚（信号） |
| 右电调信号 S | **GPIO5** | APO-DL **B 通道** S 脚（信号） |
| 电调信号地 − | **GND** | APO-DL A/B 通道 − 脚（共地，**必须接**） |
| 电调信号 + | **不接！** | APO-DL A/B 通道 + 脚悬空 |

> **为什么电调 + 脚不接？**
> 电调已经通过电池独立供电（通常 2S~4S 锂电池接到电调的电源输入端）。信号线的 + 脚是给无独立供电的小舵机用的。如果把电调的 + 脚也接到 ESP32 的 3.3V 或 5V，会造成两个电源冲突。

### 编码器连接

| 信号 | ESP32-S3 GPIO | 接到哪里 |
|------|---------------|----------|
| 左编码器 A 相 | **GPIO6** | 左电机编码器 A 相输出 |
| 左编码器 B 相 | **GPIO7** | 左电机编码器 B 相输出 |
| 右编码器 A 相 | **GPIO15** | 右电机编码器 A 相输出 |
| 右编码器 B 相 | **GPIO16** | 右电机编码器 B 相输出 |
| 编码器 VCC | 3.3V 或 5V | 按编码器模块标称电压供电 |
| 编码器 GND | **GND** | **必须与 ESP32 共地** |

> 编码器供电按模块标称（3.3–5V），必须与 ESP32 **共地**。

### APO-DL 电调各引脚作用

| 引脚 | 名称 | 作用 |
|------|------|------|
| **S** | 信号脚 | 接收 ESP32 发出的 **RC PWM 脉冲**（50Hz / 1000~2000µs）。1500µs=停止，>1500µs=正转，<1500µs=反转，数值离 1500 越远转速越高。这是 ESP32 唯一需要控制的引脚 |
| **−** | 信号地 | 与 ESP32 **GND 共地**，形成完整的信号回路。不接地则电调收不到 PWM 信号 |
| **+** | 信号正极 | 给无独立供电的小舵机用的电源输出。本项目**不接**——电调已通过电池独立供电，接上会导致电源冲突 |
| **ABS** | 电子刹车 | 硬件级急停引脚。**悬空或高电平**=电机正常运转；**接低电平(GND)**=立即刹停，不管 PWM 信号是多少。本项目未使用（悬空），停车靠 PWM 回中位 1500µs |

### 编码器 A/B 相的作用

编码器的 A 相和 B 相是**两根配合使用的信号线**，用来检测电机的**旋转速度**和**旋转方向**：

- A 相和 B 相输出两路方波信号，**相位差 90°**（正交信号）
- **正转时**：A 相领先 B 相 90°（A 先跳变，B 后跳变）
- **反转时**：B 相领先 A 相 90°（B 先跳变，A 后跳变）

程序通过 GPIO 边沿中断同时捕捉 A/B 两相的电平跳变，用查表法（`quad_table[16]`）实时解码：

```
  A/B 电平组合: 00 → 01 → 11 → 10 → 00 ...  (格雷码单步变化)
  正转: 00→01 = -1, 01→11 = +1, 11→10 = -1, 10→00 = +1  交替
  反转: 00→10 = +1, 10→11 = -1, 11→01 = +1, 01→00 = -1  交替
```

- 每次检测到有效跳变 → +1（正转一步）或 -1（反转一步）
- 无效跳变（两相同时变化=噪声）→ 0，跳过
- **4 倍频**：一个完整的 AB 周期有 4 个边沿，全部捕捉 → 分辨率是编码器标称值的 4 倍

当前程序中编码器**只读取显示**（按 `c` 查看计数），不参与电机速度闭环控制（闭环在 `算法2` 分支）。

### 电机接线方向
- **电机方向靠硬件接线**：源码里 `LEFT/RIGHT_MOTOR_REVERSE=0`，注释说明「已手动把一边电机蓝白线反接」。若你没反接线、某轮转反，有两个选择：
  1. **推荐**：硬件对调电机任意两根相线（蓝/白/红中的两根）
  2. **方便调试**：把对应 `*_MOTOR_REVERSE` 宏改成 `1`
- ⚠️ **不要两个方法同时做**（负负得正，等于没改）

## 软件架构

### 单文件、单任务、轮询模式

```
app_main()
  ├── esc_init()            ← 初始化 LEDC PWM（50Hz, 14bit）
  ├── motor_stop()          ← 确保输出 1500µs 中立信号
  ├── command_input_init()  ← 初始化 USB-JTAG 串口
  ├── encoder_init()        ← 配置 GPIO 输入 + 中断 + 4× 解码
  ├── print_help / print_status
  └── while(1) {            ← 主循环（约50Hz 非精确周期）
        ├── 非阻塞读键盘（20ms 超时）
        ├── 命令分发: w/s/a/d/x/c/z/+/-
        ├── if (电机运行中) {
        │     timeout_count += 20ms
        │     if (>= 1200ms) motor_stop()  ← 死人停车
        │ }
      }

  同时运行（硬件中断）:
  ├── left_encoder_isr()   ← GPIO 边沿触发 → 查表 → left_count++
  └── right_encoder_isr()  ← GPIO 边沿触发 → 查表 → right_count++
```

### 为什么用轮询而不是多任务？
这是**最小可用验证程序**，所有操作都是非阻塞的（串口读取 20ms 超时），单任务轮询完全足够。键到电机的响应延迟 < 20ms，人感觉不到。

算法分支（如 `follow_robot`）才会引入真正的多任务架构——每个传感器在独立 FreeRTOS 任务中运行，控制任务以精确的固定频率执行。

## 构建与烧录

### 前提条件
- 已安装 ESP-IDF v5.x（推荐 v5.1+）
- ESP-IDF 环境变量已设置（`export.sh` / `export.bat`）
- ESP32-S3 开发板通过原生 USB 口连接到电脑

### 构建步骤

```bash
# 1. 设置目标芯片
idf.py set-target esp32s3

# 2. 构建
idf.py build

# 3. 烧录并启动串口监视器
idf.py flash monitor
```

> ⚠️ 控制走的是 **USB-Serial-JTAG**（板子原生 USB 口的控制台），不是 UART0。`idf.py monitor` 连上后**直接按键**即可遥控；用别的串口助手要连到 USB-JTAG 那个口。

### 如果烧录失败
1. 检查 USB 线是否支持数据传输（不是纯充电线）
2. 按住 BOOT 键再按一下 EN 键进入下载模式
3. `idf.py monitor` 看到的波特率是运行时日志输出，跟烧录无关

## 键盘命令

| 按键 | 功能 | 左右轮关系 | 详细说明 |
|------|------|------------|----------|
| `w` | **前进** | ═ 等速正转 | 左右轮**相等**，同时输出 `1500 + speed_delta_us`，两轮同速正转，行李箱走直线向前 |
| `s` | **后退** | ═ 等速反转 | 左右轮**相等**，同时输出 `1500 - speed_delta_us`，两轮同速反转，行李箱走直线向后 |
| `a` | **左转** | ≠ 差速对开 | 左右轮**不相等**——左轮 `1500 - speed_delta_us`（反转），右轮 `1500 + speed_delta_us`（正转），两轮速度绝对值相等、方向相反，行李箱原地差速左转 |
| `d` | **右转** | ≠ 差速对开 | 左右轮**不相等**——左轮 `1500 + speed_delta_us`（正转），右轮 `1500 - speed_delta_us`（反转），两轮速度绝对值相等、方向相反，行李箱原地差速右转 |
| `x` | **立即停止** | ═ 等同中位 | 回到 1500µs 中位，左右轮**同时置中**，同时清除运行状态 |
| `c` | **显示编码器** | — | 打印左右编码器的当前累加计数值 |
| `z` | **显示状态** | — | 打印全部状态：速度力度、当前脉宽、编码器计数、反转标志 |
| `+` / `-` | **调整速度** | ═ 两侧同变 | 每次 ±50µs 步进，范围 100–500µs，左右轮的 `speed_delta_us` **始终相等** |
| `h` | **帮助** | — | 重新打印按键列表 |

### 差速转向的数学逻辑

```
左轮脉宽 = 1500 + speed_delta × 左方向系数
右轮脉宽 = 1500 + speed_delta × 右方向系数

         左系数  右系数   左右关系       物理效果
  ────────────────────────────────────────────────
  w(前进)   +1     +1    相等 (左=右)    两轮同速正转，直线前进
  s(后退)   -1     -1    相等 (左=右)    两轮同速反转，直线后退
  a(左转)   -1     +1    不等 (左≠右)    左反转右正转，原地左转
  d(右转)   +1     -1    不等 (左≠右)    左正转右反转，原地右转
  x(停止)    0      0    相等 (左=右)    两轮回到1500µs中位
  ────────────────────────────────────────────────

 总结：
   w/s(前进/后退) — 左右轮相等 (等速)，走直线
   a/d(左转/右转) — 左右轮不等 (差速对开)，原地转向
   speed_delta_us 对左右轮始终相同，只是正负号不同
```

> 默认 `speed_delta_us=300` →
>   前进: 左=1800µs, 右=1800µs（相等）&nbsp;&nbsp;|&nbsp;&nbsp;
>   后退: 左=1200µs, 右=1200µs（相等）&nbsp;&nbsp;|&nbsp;&nbsp;
>   左转: 左=1200µs, 右=1800µs（不等）&nbsp;&nbsp;|&nbsp;&nbsp;
>   右转: 左=1800µs, 右=1200µs（不等）

`main.c` 是一个完整的、可编译的 ESP-IDF 程序，约 400+ 行。以下是各部分的阅读指南：

| 行数范围 | 区域 | 关键内容 |
|----------|------|----------|

### 特别关注的关键实现

**1. 编码器 4× 解码查表法（`quad_table` + ISR）**

这是最高效的增量编码器读取方式：
- 表占用 16 字节，索引由 `(上一次的A<<1|上一次的B) << 2 | (当前的A<<1|当前的B)` 计算
- 查表直接得到 `+1`（正转）、`-1`（反转）或 `0`（无效跳变）
- ISR 中零判断、零分支，极短执行时间
- 这张表和 `算法2` 的 `components/control/chassis/chassis.c` 完全一致

**2. PWM 占空比换算（`pulse_us_to_duty`）**

```
duty = pulse_us * 16383 / 20000
1500µs → 1500 * 16383 / 20000 ≈ 1229
```

在 14 位分辨率下，每个 duty 单位 ≈ 1.22µs，精度远超 RC 电调所需。

**3. 死人停车计时器**

```
if (motor_running) {
    timeout_count += 20;    // 每次主循环加20ms
    if (timeout_count >= 1200) {
        motor_stop();       // 1.2秒到，强制停止
    }
}
```

## 操作流程（首次接线验证）

### 第 1 步：架空调试（⚠️ 安全必须）
1. **把行李箱架空**，让两个后轮悬空（用砖块/书本垫高）
2. 接通电调电源（电池），听到电调"滴滴"自检声
3. 烧录程序并启动 `idf.py monitor`
4. 看到输出内容后，按 `w` 键
5. **确认两个后轮都朝前进方向旋转**（从上往下看，两个轮子都应该向前转）
6. 如果有轮子转反：
   - 断开电源，把该轮电机的任意两根相线对调（蓝白对调、红蓝对调均可）
   - 或者把对应的 `*_MOTOR_REVERSE` 宏改成 `1` 再重新编译
7. 按 `s` 确认后退方向正确
8. 按 `a`/`d` 确认左右转向正确
9. 旋转轮子时按 `c` 确认编码器计数在增加（正转应增加，反转应减少）

### 第 2 步：落地慢速测试
1. 按 `-` 把速度降到最小（`speed_delta_us=100`）
2. 把行李箱轻轻放到地面上
3. 按 `w` 看行李箱是否缓慢向前移动
4. 逐步按 `+` 增加速度，找到感觉舒适的 `speed_delta_us`
5. 记录下这个值，未来算法分支可参考

### 第 3 步：编码器标定
1. 在地面上量出 1 米距离并做标记
2. 按 `z` 记录当前编码器计数
3. 按 `w` 让行李箱走完 1 米
4. 按 `x` 停止，再按 `c` 查看计数
5. 计算：`ticks_per_meter = 最终计数 - 初始计数`
6. 这个值填入算法分支的 `CONFIG_*_TICKS_PER_METER` Kconfig

## ⚠️ 注意事项 / 安全（无刷电机，务必小心）

1. **第一次务必架空轮子**：无刷电机+电调力气大、转速高，落地直接窜出去很危险。先垫高空转确认方向再落地。

2. **电调要先解锁/校准中位**：上电程序立即输出 1500µs。**如果电调被复位过，需要在 1500µs 处重新做一次中位校准**（按电调说明书操作），否则可能不动或乱转。本分支没有显式 arming 延时（`算法2` 才加了 `ESC_ARM_MS`），上电就给 1500，等电调"滴滴"自检完成再操作。

3. **死人停车 1.2s**：按一下只走 1.2s 就停，是**有意的安全设计**，不是 bug——要持续走就持续按键。`x` 立即停。

4. **编码器是开环只读**：本分支**不**用编码器做速度闭环（没有 PID），计数仅供观察/标定。闭环在 `算法2`。

5. **电机转反怎么办**：
   - **推荐**：硬件对调电机任意两根相线（物理修正，永久生效）
   - **临时调试**：把对应 `*_MOTOR_REVERSE` 改 `1` 用软件反向
   - ⚠️ 两者**不要同时做**

6. **控制口是 USB-JTAG**：连错串口会没反应；用板子的原生 USB 口 + `idf.py monitor`。

7. **共地**：电调信号地、编码器地必须与 ESP32 **共同接地(GND)**，否则信号不稳或完全无信号。

8. **电池安全**：
   - 锂电池（LiPo）过放会永久损坏，注意电压不要低于 3.3V/节
   - 调试完毕记得拔电池（电调待机也会耗电）
   - 充电时远离易燃物，不要离开视线
   - 电池鼓包立即停用并妥善回收

9. **电调发热**：长时间大电流运行时电调会发热。如果手摸感到烫（>60°C），应立即停止检查电机负载是否过大。

## 故障排查

| 现象 | 可能原因 | 解决方法 |
|------|----------|----------|
| 上电后电调一直滴滴响 | 电调未收到有效 PWM 信号 | 检查 GPIO4/5 接线、检查共地 |
| 按 w 电机不转 | speed_delta_us 太小 / 电调未解锁 | 按 + 增大速度 / 等待电调自检完成 |
| 前进时一个轮子正转一个反转 | 该轮电机三相线接反了 | 对调该轮任意两根相线 |
| 编码器计数不动 | 编码器供电问题 / 未共地 | 测量编码器 VCC 电压、检查 GND 连接 |
| 编码器计数反转（正转减少） | A/B 相接线顺序反了 | 对调 A/B 两相的接线 |
| `idf.py monitor` 无输出 | 串口选错了 / USB 线不支持数据 | 确保用板子原生 USB 口、换一根数据线 |
| 电机抖动但不转 | 电调缺相（三相中有一相断开） | 检查电机三相线是否连接牢靠 |
| 运行时突然停止 | 死人停车生效 / 电池电压过低 | 继续按键 / 给电池充电 |

## 技术要点备忘

### 为什么 50Hz 而不是更高频率？
- APO-DL 电调兼容标准 RC 50Hz 信号
- 更高频率（如 400Hz）需要"数字伺服"或"OneShot125"等特殊协议
- 50Hz 的 20ms 周期足够长，信号不易受电机电磁干扰影响
- 20ms 延迟对人对控制来说完全感觉不到

### 为什么 14 位而不是 16 位？
- 在 50Hz 低频下，16 位分辨率的时钟分频不够用
- 14 位下每个占空比单位 ≈ 1.22µs，已远超 RC 电调的辨识能力（~2-4µs）
- 更高的位数在 50Hz 下没有实际意义

### 编码器计数的 64 位存储
- 32 位有符号整数最大值约 21 亿（±2^31）
- 假设每圈 1000 个 4× 脉冲，轮子周长 0.3m，持续运行：
  - 每秒 3000 脉冲 → 约 200 小时才会溢出 32 位
- 用 64 位（±9.2×10^18）基本不会溢出，无需担心
