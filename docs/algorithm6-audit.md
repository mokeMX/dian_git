## 资源清单

- 任务：`control`(6144/7/50 Hz)、`uwb`(4096/6)、`lidar`(4096/6)、`ultra_left`(3072/5)、`ultra_right`(3072/5)、`fsr`(3072/3)，另有 ESP-IDF HTTP/Wi-Fi 系统任务。
- 互斥锁：传感器快照锁、网页状态锁。
- 队列/事件组：业务代码未使用；UART 驱动和 Wi-Fi 内部管理其队列。
- UART：UWB 独占 UART1；RPLIDAR 独占 UART2；超声波使用两个独立软件接收器。
- PWM：LEDC low-speed timer 0，channel 0/1。
- ADC：ADC1 channel 7，oneshot。
- 数据流：传感器任务 → 带时间戳快照 → 控制任务 → 权限/安全仲裁 → 底盘唯一接口 → LEDC。

## 已发现并修复的问题

1. `算法4` 的雷达过滤代码含 Git 冲突标记。
2. UART 和超声波引脚与固定约束不符。
3. 被移除传感器仅被注释，源码、配置、任务仍存在。
4. 主工程未采集 FSR，网页控制组件缺失。
5. 控制任务忽略部分 `esp_err_t`，底盘 LEDC 写入不传播错误。
6. 编码器断线时仍靠前馈继续运行。
7. 主机测试把 ESP-IDF 硬件源直接交给 GCC，无法编译；现已拆出纯 C 数学和解析文件。

## 引脚风险结论

仓库只证明目标为 ESP32-S3，未提供具体开发板/模组料号和原理图。因此软件冲突已排除，但无法从仓库证实 GPIO47/48 是否连接板载 RGB LED，也无法证实 GPIO38/39 是否与某个 Octal Flash/PSRAM 板型硬连。算法6按指定引脚实现，烧录前必须用实际板卡原理图复核，不能把“编译通过”当作硬件兼容证明。
